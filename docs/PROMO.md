
## 正文

```
做视频整理的时候一直有个痛点：过一遍片子找可用的镜头，用普通播放器特别难受。

拖进度条要么一下跳过，要么拖半天找不到那两秒；想标记"这段能用"，只能在纸上记时间码；
记完还得在剪辑软件里重新对一遍时间。整个流程是断的。

所以写了个工具，把这三步连起来：

1. 刷片 —— 触摸板左右推拉就是带惯性的快进快退。慢速微调时自动切到精确 seek，
   快速拖动只跳关键帧，所以画面能一直跟手，不会卡住。
2. 打点 —— A/B/C/D/F/G 六种标记，随手按，右侧列表实时出来。
3. 出片 —— [ ] 划出入点生成区间，应用内直接剪片段，或者几个区间合并成一条。
   也能导出 CSV / EDL 给 Premiere、达芬奇。

技术上是 Electron + mpv（--wid 嵌入原生子窗口）+ ffmpeg。选 mpv 是为了格式兼容性，
它基本什么都能放。

几个自己踩的坑，可能对做类似东西的人有用：

- seek 策略是手感的关键。全程用 exact seek 必卡，因为要从上一个关键帧逐帧解码，
  长 GOP 能到 1.2 秒。正确做法是拖动中发 keyframes、松手补一次 exact。
  这个思路是抄 mpv 官方 OSC 和 LosslessCut 的。
- 重编码体积翻车：原来固定 CRF 23，结果 165MB 的素材剪完变 365MB。
  改成按源文件码率（大小 ÷ 时长 − 音轨）做 ABR 才对。
- 标记存 sidecar 时，扩展名要追加（a.mp4.markplay.json）而不是替换，
  否则 a.mp4 和 a.mkv 会互相覆盖。

比较明确的缺点，先讲清楚：

- 安装包没签名，Windows 首次运行会弹"未知发布者"，点"更多信息 → 仍要运行"。
- 视频画面是原生子窗口，所以 HTML 控件盖不上去，控制条只能放在画面下方。
- 只支持 Windows 10/11。
- 触摸板手感跟驱动有关，不同机器差异挺大，config.js 里留了参数可以自己调。

仓库（MIT）：https://github.com/glowwan/markplay

想听两件事：
1. 有没有人跟我一样是"过片找点"这种工作流，你们现在怎么做的？
2. 触摸板刷片这个交互，是不是我想当然了——鼠标党会不会觉得没意义？

轻喷，代码是自己一点点抠出来的。
```

## 正文

```
## 先说痛点

整理素材时，我们其实在重复三个动作：快速过一遍片子，把能用的地方记下来，再回头精确剪出来。

听起来简单，但用通用播放器做这件事是断的。

拖进度条要么一下跳过、要么拖半天找不到那两秒；想标记"这里不错"，
只能在纸上记时间码，或者切到记事本敲数字；记完之后，还得在剪辑软件里
把每个时间点重新对一遍。

这三个动作之间每一次切换，都在消耗注意力。

## 所以做了一个工具

MarkPlay 是一个 Windows 上的视频播放器，把这三步做成一套连贯的操作。

它底下用的是 mpv，所以格式兼容性基本不用担心——MKV、TS、各种奇怪的编码都能直接放。
上层用 Electron 做了界面，把打点、区间、剪辑包了起来。

## 一、刷片：触摸板推拉

这是整个工具里调整最久的部分。

把触摸板当滚轮用：**左右推拉就是快进快退**，而且带惯性——手指离开之后画面还会滑一段，
像滚动网页那样自然。

关键在于"跟手"。早期版本拖动时会明显卡顿，原因是每次拖动都做精确 seek：
播放器必须从前一个关键帧开始逐帧解码，长 GOP 的片子一次要 1.2 秒，
拖动中不断发命令就直接积压了。

后来的做法是分速度：拖得快时只跳关键帧（5~50 毫秒，画面连续跟手），
拖得慢、做微调时才用精确 seek，松手时再补一次精确定位。

（配图位置 1：优先录一段刷片动图；暂时没有的话，先用仓库首屏那张静态界面图，把"推拉手感"用文字交代清楚）

纵向推拉则是调音量。

## 二、打点：六种标记，随手按

播到某处按 A（或 B/C/D/F/G），就在当前时间打一个标记。
右侧列表实时出现条目，点一下能跳回去。

六种类型主要是为了区分用途，比如 A 标"候选"、B 标"必用"、C 标"待定"。
每种类型独立编号（A1、A2、B1…）。

标记可以双击改名、拖时间轴上的刻度直接改时间、Delete 删除、Ctrl+Z 撤销。

（配图位置 2：打点动图；同样可以先用静态截图，重点是让读者看到"右侧列表实时新增条目"这个反馈）

## 三、出片：划出入点，直接剪

按 `[` 设入点、`]` 设出点，就生成一个"区间"。

区间是显式的 in/out，不是从标记里猜出来的配对。这一点在批量处理时差别很大：
你可以只打 A/B 点让它自动配对，也可以完全按时间顺序相邻两个一组，
或者手动一段段划。

有了区间之后：

- **剪一段**：选区间 → 开始剪辑，直接出文件
- **批量剪**：每个区间各出一个
- **合并**：所有区间按顺序拼成一条

剪辑走 ffmpeg。默认是 `-c copy`（快、无损，但切点会落在关键帧上），
勾选"重新编码"可以精确到帧。

这里有个坑值得说：最初固定用 CRF 23 重编码，结果 165MB 的素材剪完变成 365MB。
原因是 CRF 是"按质量给码率"，源文件本身码率低的时候反而被压大了。
后来改成按源文件码率反算（文件大小 ÷ 时长 − 音轨码率）做 ABR，体积才回到合理范围。

## 四、导出给剪辑软件

标记和区间都能导出：

- 标记 CSV / 区间 CSV：带秒数、时间码、帧号
- EDL：CMX3600 格式，多数剪辑软件能认
- JSON：给需要二次处理的人

帧号会跟随素材真实帧率——23.976 按 24、29.97 按 30 的名义帧率算非丢帧时间码，
不再一律按 25fps 硬算。

## 它还不完善

说实话的部分：

- **安装包没有代码签名**。Windows 首次运行会弹"未知发布者"，点"更多信息 → 仍要运行"即可。
  个人项目没买证书，这是现状。
- **控制条不能悬浮在画面上**。因为视频画面是 mpv 的原生子窗口，HTML 控件盖不上去，
  所以控制条放在画面下方。
- **只支持 Windows 10/11 x64**。
- **触摸板手感因机而异**。不同品牌的驱动差异很大，参数留在 config.js 里可以自己调。
- **合并剪辑必然重新编码**，不是无损拼接。

## 适合谁

- 经常要"过片找点"的人：素材整理、纪录片粗剪、访谈挑片段
- 需要在没有剪辑软件的机器上快速标记素材的人
- 想用一套快捷键把"看—记—剪"连起来，不想来回切窗口的人

如果你只是偶尔剪个短视频，用剪映之类的更省事，这个工具对你可能过重了。

项目是 MIT 开源的：https://github.com/glowwan/markplay

```

# 四、通用建议

1. **先发 B 站/小红书，再发技术社区。** 视频素材可以复用到所有平台。
2. **不要一天全平台铺开。** 分开几天发，每个平台都能认真回评论。
3. **每次发帖后 24 小时内盯着评论区。** 早期反馈比 star 值钱——你现在的版本还在快速迭代，第一批用户的抱怨就是路线图。
4. **star 数不要当 KPI。** 这个品类天花板不高（LosslessCut 做了很多年也就三万多）。有几十个真实用户在用、愿意提 issue，比几百个 star 有意义。
5. **持续提交。** 每周哪怕一个小改动，仓库活跃度会体现在搜索结果和别人的信任度上。
